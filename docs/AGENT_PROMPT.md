# Промпт для ИИ-агента (Claude Code и т.п.)

Запускай агента в корне репозитория (там, где лежит `descriptor.mod`), с доступом к папке игры HoI4 на чтение.

```
Ты разрабатываешь мод «Lean Late Game» для Hearts of Iron IV. Цель мода — снизить нагрузку на CPU в поздней игре (1943+), не меняя баланс и историю заметнее, чем необходимо. Репозиторий уже содержит каркас: прочитай README.md, docs/ROADMAP.md и docs/BENCHMARK.md.

ПУТИ
- Ваниль (только чтение): C:\Program Files (x86)\Steam\steamapps\common\Hearts of Iron IV
- Моды: C:\Users\<USER>\Documents\Paradox Interactive\Hearts of Iron IV\mod
- Логи: ...\Hearts of Iron IV\logs (error.log — проверять после каждого изменения)
(Если пути другие — спроси один раз и запомни.)

ПРАВИЛА
1. Никакой правки «по памяти». Любое имя define, триггера, эффекта или файла сначала находи в ванильных файлах ТЕКУЩЕЙ версии игры и копируй структуру оттуда. Если не уверен — скажи об этом, не выдумывай.
2. Ванильные файлы не копируй в репозиторий целиком (авторские права Paradox). Переопределяй минимально: либо отдельным файлом с zz_-префиксом (defines), либо файлом с тем же именем, содержащим только изменённые блоки, где движок это допускает. Не используй replace_path без крайней необходимости.
3. Один логический шаг = один коммит с понятным сообщением (Conventional Commits: feat/fix/docs/chore). Каждое изменение отражай в CHANGELOG.md.
4. Любая «оптимизация» должна быть подтверждена замером по docs/BENCHMARK.md. Если замерить нельзя (нет игры/сейва), так и пиши и помечай изменение как непроверенное.
5. После каждого изменения проверяй error.log на ошибки парсинга. Ошибки мода — приоритет №1.
6. Не ломай ачивки/сохранения без явного предупреждения в README.

ПОРЯДОК РАБОТЫ
Шаг 1. Составь аудит: где в ванили самая тяжёлая работа в late game. Просмотри common/defines/00_defines.lua (секции NAI, NMilitary, NSupply и т.п.), common/ai_strategy, common/on_actions (on_daily, on_weekly, on_monthly), common/scripted_effects и scripted_triggers с циклами every_country / every_state / every_unit_leader. Выдай список кандидатов на оптимизацию с оценкой риска и ожидаемого эффекта. Остановись и покажи мне список до внесения правок.
Шаг 2. После моего подтверждения реализуй по одному пункту в порядке: defines → ИИ малых стран → шаблоны ИИ → on_actions.
Шаг 3. Для каждого пункта: правка, проверка error.log, запись в CHANGELOG, обновление ROADMAP, коммит.
Шаг 4. Когда я пришлю цифры замеров, занеси их в docs/BENCHMARK.md и предложи следующий шаг.

ФОРМАТ ОТВЕТОВ
Коротко: что изменил, какие файлы, чем рискуем, как проверить. Без воды.
```
